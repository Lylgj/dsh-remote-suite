# 使用指南

这个插件做两件事：

1. 在 DeepSeek Harness 的「添加工作区」对话框里多出 **本机 / WSL / Docker / 远程 SSH** 四个标签页；
2. 给每个 agent preset 一个 `remote` 工具，用同一套参数在任意目标上执行命令、读写文件、同步目录。

下面按「装 → 加工作区 → 在会话里用 → 各种细节 → 出问题怎么办」的顺序写。

---

## 1. 安装

### 前提

| 项目 | 要求 |
|---|---|
| DeepSeek Harness | `>= 0.2.1-rc.2` |
| Node（Host 进程） | `>= 20` |
| Windows | 本机、WSL2、SSH、Docker（走 `docker` CLI）都可用 |
| macOS / Linux | 本机、SSH、Docker 可用；WSL 目标只在 Windows 上出现 |

### 安装

```powershell
dsh plugin --profile desktop add "file:D:\path\to\dsh-remote-suite"
```

路径换成插件所在目录。装完**完全重启** DeepSeek Harness（不是刷新页面——插件是这样加载的）。

### 确认装上了

- 每个 agent preset 的工具列表里多出 `remote`；
- 点工作区列表旁的 `＋`，对话框标题是「添加工作区」，里面是四个标签页。

### 和同类插件冲突

`dsh-wsl-tool`、`dsh-wsl-workspace`、`@zhangfengshun/dsh-remote-ssh` 会注册同名工具或抢占侧栏，
先卸掉：

```powershell
dsh plugin --profile desktop remove dsh-wsl-tool
dsh plugin --profile desktop remove dsh-wsl-workspace
dsh plugin --profile desktop remove @zhangfengshun/dsh-remote-ssh
```

### 卸载

```powershell
dsh plugin --profile desktop remove dsh-remote-suite
```

注意：如果这个插件是以 `file:` 目录方式安装的，**卸载前不要删掉或改名那个目录**——pnpm 剪依赖时
要去打包它，目录不在就会整条 install 失败，插件处于半卸载状态。真遇到了，看插件管理器日志
`.plugin-manager\logs\operation-*\pnpm.log` 的第一行，把它指回一个存在的路径即可。

## 2. 添加工作区

### 对话框结构

从上到下：

1. **四个标签页**：本机 / WSL / Docker / 远程 SSH；
2. **目标行**：本机页是盘符按钮，其余是目标下拉框；远程 SSH 页右侧还有「＋ 新增」「删除」；
3. **路径行**：输入框 + 「上级」+「主目录」。回车等于「浏览到这条路径」；
4. **目录列表**：只列子目录，点一下进入；
5. 底部「取消」「创建并打开」。

只能选**已经存在**的目录；对话框不会替你新建目录。

打开时**不预选任何目标**：先在目标行里选一台主机 / 一个发行版 / 一个容器，下面的列表就跳到它的主目录。
路径框留空直接点「创建并打开」，用的也是主目录。

### 本机

盘符按钮列出这台机器上存在的盘（`C:\`、`D:\`……）。选盘 → 逐级进入 → 「创建并打开」。

工作区路径就是本机真实路径，DSH 的文件树、终端、`git` 全部照常。

### WSL

下拉框自动列出已安装的发行版（来自 `wsl.exe -l -q`）。路径写发行版内的 Linux 路径，比如
`/home/you/project`。

创建后工作区指向 `\\wsl.localhost\<发行版>\<路径>`——这是 Windows 上可以直接访问的真目录，
所以文件树、终端都对，**不经过镜像**。

刚装的发行版要等下一次刷新（约 10 秒）才会出现在下拉框里。

### Docker

下拉框列出**正在运行**的容器（`docker ps`）。路径写容器内路径，比如 `/app`。

创建后工作区打开的是本地镜像目录（见「2.5 工作区打开后是什么」），真正的容器内文件用 `remote`
工具读写，`target` 写 `docker:<容器名>`。

要求：容器是 Linux、里面有 `sh`。引擎不是 `docker` 的话，设环境变量 `DSH_DOCKER`（如 `podman`）。

### 远程 SSH

**目标下拉框**里的主机有两个来源：

- `~/.ssh/config` 里的每个非通配 `Host`（`HostName`、`User`、`Port`、`IdentityFile`、`ProxyJump` 都生效）；
- 在这个对话框里新增的主机。

两者在下拉框里混在一起，插件不知道谁是哪个来源，统一按别名引用。

**「＋ 新增」** 打开「新增 SSH 主机」表单：

| 字段 | 说明 |
|---|---|
| 别名 | 1–64 个字，可以用中文，只允许字母、数字、`.`、`-`、`_`；不能有空格、冒号、斜杠。它只是插件内部的标识，**不会写回** `~/.ssh/config` |
| 主机 | 主机名或 IP |
| 用户 | 可空，空则用 `~/.ssh/config` 里的 `User`，再空则用当前用户名 |
| 端口 | 可空，默认 22 |
| 私钥 | 可空。点「选择」打开文件选择器（顶部有盘符按钮，底部有「使用此路径」）；留空就按下面的认证顺序自动找 |
| 密码 | 可空，填了会存进 `secrets.json`（0600，且从不回显） |

点「保存并选用」：主机存下来、下拉框选中它、页面切回「远程 SSH」。

**「删除」** 打开「管理 SSH 主机」弹窗，列出全部主机：

- 在本插件新增的 —— 有「删除」按钮，连存储的密码一起删掉；
- 来自 `~/.ssh/config` 的 —— 标着 `~/.ssh/config` 和一个「在那个文件里编辑」的提示，不能在这里删。
  那个文件是用户自己的，插件不改写它。

选中主机后，下面的目录列表就是那台机器上的目录；选好路径点「创建并打开」。

### 工作区打开后是什么

插件先把路径交给 Host，Host 按普通工作区创建。交出去的那条路径取决于目标类型：

| 目标 | 工作区路径 | 文件树 / 终端看到的是 |
|---|---|---|
| 本机 | 原路径 | 本机真实文件 |
| WSL | `\\wsl.localhost\<发行版>\<路径>` | 发行版里的真实文件 |
| Docker | `$DSH_HOME/remote-suite/mirrors/<id>` | **本地镜像目录**（初始为空） |
| 远程 SSH / 会话 | `$DSH_HOME/remote-suite/mirrors/<id>` | **本地镜像目录**（初始为空） |

也就是说：Docker 和 SSH 的工作区在 DSH 里是个本地目录，真正的内容还在远端。想让文件树里有东西，
用镜像同步（见第 6 节）把远端拉下来；日常读写远端文件直接用 `remote` 工具更准。

## 3. 在会话里操作远端：`remote` 工具

### 目标 id

| 形式 | 含义 | 标签示例 |
|---|---|---|
| `local` | 本机 | 此电脑 |
| `wsl:<发行版>` | 某个 WSL 发行版 | `WSL · Ubuntu` |
| `ssh:<别名>` | 一个 SSH 主机 | `SSH · 云服务器` |
| `daemon:<别名>` | 同一个主机的常驻会话（见第 5 节） | `SSH · 云服务器 (session)` |
| `docker:<容器名>` | 运行中的容器 | `Docker · web` |

不知道有什么时，先 `remote action=targets`。

### 通用参数

- `target`：目标 id，上表之一。
- `workspace`：已保存的工作区 id，**与 `target` 互斥**。传了它，`path` 相对该目录解析，`exec` 的
  默认工作目录也落在那里——长会话里想少写绝对路径就用它。
- `path`：目标内的路径。相对路径按 `workspace` 基准解析；没有 `workspace` 时按目标主目录/当前目录。

### action 一览

| action | 关键参数 | 做什么 |
|---|---|---|
| `targets` | — | 列出所有目标 id |
| `workspaces` | — | 列出已保存的 `(目标, 目录)` |
| `workspace-add` | `target`、`path`、`name?` | 保存一个工作区；路径必须是目录，id 冲突时自动加后缀 |
| `workspace-remove` | `workspace` | 删除保存项（不动磁盘上的文件） |
| `probe` | `target` / `workspace` | 目标到底是什么：系统、平台、node 版本、当前目录 |
| `exec` | `command`、`workdir?`、`timeoutMs?` | 跑一条 shell 命令 |
| `read` | `path`、`offset?`、`limit?` | 读文件，带行号，可以只读一段 |
| `write` | `path`、`data` | 整体覆盖写 |
| `edit` | `path`、`old`、`new`、`replaceAll?` | 原地替换；默认要求 `old` 只出现一次，否则报错而不是乱改 |
| `stat` | `path` | 类型与大小 |
| `list` | `path`、`limit?` | 目录条目（默认 500 条） |
| `grep` | `pattern`、`path?`、`glob?`、`ignoreCase?`、`limit?` | 内容搜索（正则） |
| `glob` | `pattern`、`root?`、`limit?` | 按文件名模式找文件 |
| `secret-set` / `secret-remove` | `target`、`password` | 保存 / 忘记某台主机的 SSH 密码 |
| `mirrors` | — | 列出镜像 |
| `mirror-add` | `target`、`path`、`name?`、`local?` | 登记一个远端目录做镜像 |
| `mirror-remove` | `mirror` | 取消登记（本地副本留在磁盘上） |
| `mirror-sync` | `mirror`、`direction`、`force?`、`dryRun?` | `pull` 远端→本地，`push` 本地→远端 |

### 例子

```text
remote action=targets

remote action=exec target=ssh:云服务器 command="systemctl status nginx"

remote action=exec target=wsl:Ubuntu workspace=app command="npm test" timeoutMs=300000

remote action=grep target=ssh:云服务器 path=/srv/app pattern="TODO" glob="*.ts"

remote action=glob target=docker:web pattern="**/*.env" root=/app

remote action=edit target=ssh:云服务器 path=/srv/app/.env old="DEBUG=false" new="DEBUG=true"
```

`exec` 的输出形如：

```text
[SSH · 云服务器] exit=0
<标准输出>

--- stderr ---
<错误输出>
```

超时或输出过长会在第一行标出来（`timed out` / `output truncated`），单次输出上限 64 KB，
默认超时 120 秒。

`grep` / `glob` 在目标上有 `rg` 时用 `rg`，没有就退到 `grep -rnIE` / `find`，功能一样，慢一些。

## 4. SSH 认证与密码

### 认证顺序

1. `DSH_SSH_IDENTITY` 环境变量（`;` 分隔多个私钥路径，CI 里用）；
2. `~/.ssh/config` 或新增主机里写的 `IdentityFile`；
3. `~/.ssh/id_ed25519`、`id_rsa`、`id_ecdsa`；
4. `ssh-agent`（`SSH_AUTH_SOCK`；Windows 上是 OpenSSH agent 管道）；
5. 已保存的密码，或环境变量 `DSH_SSH_PASSWORD`。

一个都没有可用时，报错会告诉你下一步能做什么。

### 保存密码

对话框里的「密码」字段是最省事的方式。没有界面时：

```text
remote action=secret-set target=ssh:云服务器 password=……
remote action=secret-remove target=ssh:云服务器
```

密码存在 `$DSH_HOME/remote-suite/secrets.json`，权限 0600，和 `state.json` 分开，且从不回显。

查找键是 `user@host`，**与端口无关**：换了端口还能取回同一个密码；换了用户就是另一个账户，取不到。

### ProxyJump

`~/.ssh/config` 里照着写就行，支持任意跳数，跳板可以写别名，也可以写 `user@host:port`，逗号分隔：

```text
Host target
  HostName 10.0.0.8
  User deploy
  ProxyJump bastion,ops@10.0.0.2:2222
```

## 5. 常驻会话（daemon）

每个 SSH 主机同时以 `daemon:<别名>` 出现。连接完全一样，区别在于：普通 `ssh:` 目标的每条命令
都是独立的 shell，而 `daemon:` 的所有 `exec` 共用一条非交互 bash，于是 `cd`、`export`、shell 函数
能跨命令保留。

```text
remote action=exec target=daemon:云服务器 command="cd /srv/app"
remote action=exec target=daemon:云服务器 command="pwd"        # /srv/app
```

文件工具仍然走同一条连接上的 SFTP，不受影响。

什么时候用：需要在远端维持环境（虚拟环境、`nvm`、一堆环境变量）、或者要在远端起一个长时间跑的
服务。不需要这些就用 `ssh:`，更干净。

命令里执行 `exit` 会把这个 shell 关掉，插件会如实报 `the session ended while running this command`，
下一次调用自动开一个新的。

### 在远端跑 DSH 本身

```text
remote action=exec target=daemon:云服务器 command="cd ~/app && nohup dsh web --port 8080 >/tmp/dsh.log 2>&1 &"
```

之后在本地看 `http://127.0.0.1:8080` 需要一条隧道——见第 7 节。

## 6. 镜像同步

镜像是远端目录在本地的一份副本，方便桌面侧用编辑器、全文搜索和 `git`。

```text
remote action=mirror-add target=wsl:Ubuntu path=/srv/app name=app
remote action=mirror-sync mirror=mir-app direction=pull     # 远端 → 本地
remote action=mirror-sync mirror=mir-app direction=push     # 本地 → 远端
remote action=mirrors
```

- 默认放 `$DSH_HOME/remote-suite/mirrors/<id>`，`mirror-add` 时可用 `local=` 换位置。
- 传输是 32 KB 一块的 `dd … | base64`，走目标自己的 `exec` 通道：远端不需要 `tar`、`rsync`、
  额外端口，二进制文件也不坏。
- **pull 从不删除本地文件**，只补新文件、更新旧文件。
- **push 不会盲目覆盖**：远端那份比本地新超过 2 秒就算冲突，跳过并报告；确实要覆盖就加 `force=true`。
- 先看计划不落盘：`dryRun=true`。

## 7. 端口转发

把远端端口映射到本地 loopback，用来在看板里打开远端服务：

```text
POST /remote-suite/api/forward   { "target": "daemon:云服务器", "port": 8080, "host": "127.0.0.1" }
```

（`host` 可空，默认 `127.0.0.1`，指远端那一侧要连的地址。）返回
`{ id, url: "http://127.0.0.1:<本地端口>", port, remotePort }`，关掉用
`POST /remote-suite/api/forward-close  { "forward": "<id>" }`。

监听只绑 loopback，远端端口不会暴露到网络上；只有 SSH / daemon 目标能转发。

这条能力目前只通过 HTTP API 暴露，**默认界面上没有入口**：插件带的完整「远程」面板（文件树、
编辑器页签、命令控制台、xterm 终端、转发出来的 web 页签）默认不注册，`client.js` 的 `apply()`
里只挂了「添加工作区」两个 seat。想用，需要在 `apply()` 里额外注册 `sidebar.panellist` 与 `main`
两个 seat——面板本身、`/remote-suite/pty` 桥与资源路由都已经在包里了。

## 8. 环境变量

| 变量 | 作用 |
|---|---|
| `DSH_SSH_CONFIG` | 换一份 SSH 配置文件（默认 `~/.ssh/config`） |
| `DSH_SSH_IDENTITY` | 额外私钥，`;` 分隔，优先于 `IdentityFile` |
| `DSH_SSH_PASSWORD` | SSH 密码（CI 用，优先于已保存的密码） |
| `DSH_DOCKER` | 换 Docker 引擎二进制，如 `podman`、`nerdctl` |
| `DSH_WSL_EXE` | `wsl.exe` 的路径 |
| `DSH_REMOTE_SHELL` | 本机终端用哪个 shell（默认 Windows 上是 PowerShell） |
| `DSH_REMOTE_SUITE_STATE` | `state.json` 的位置 |
| `DSH_REMOTE_SUITE_SECRETS` | `secrets.json` 的位置 |
| `DSH_HOME` | 以上默认路径的根目录（默认 `~/.dsh`） |

## 9. 数据文件

都在 `$DSH_HOME/remote-suite/` 下：

| 路径 | 内容 |
|---|---|
| `state.json` | 工作区列表、镜像登记、新增的 SSH 主机（原子写） |
| `secrets.json` | `user@host` → 密码，0600，从不回显 |
| `mirrors/<id>/` | 镜像内容 |
| `debug.log` | 到达 API / WebSocket 的请求摘要，排障用 |

Windows 上 0600 不生效，实际保护靠 profile 目录的 ACL。

## 10. 常见问题

**装好了但对话框还是原生的 / 没有 `remote` 工具**
没重启，或者没重启干净。完全退出 DeepSeek Harness 再开。

**提示 `tool "wsl" is already registered`**
旧插件还在，按第 1 节卸掉，重启。

**保存主机时报别名错误**
别名不能用空格、冒号、斜杠，长度 1–64。中文没问题。报错会显示在表单里，改掉再保存。

**SSH 登录失败（`all authentication methods failed`）**
按顺序排查：`IdentityFile` / `DSH_SSH_IDENTITY` 指向的私钥对不对 → `ssh-agent` 里有没有 key →
用 `remote action=secret-set` 存密码。`remote action=probe` 能确认这个别名解析到的是哪台机器。

**WSL 下拉框里没有发行版**
`wsl -l -q` 得能列出它。刚装的等 10 秒刷新；插件运行中被删掉的发行版会在下一次刷新时消失。

**Docker 下拉框是空的**
`docker ps` 得有输出——Docker Desktop 在跑、`DOCKER_HOST` 设对了，或者 `DSH_DOCKER` 指到
`podman` / `nerdctl`。容器处于停止状态不算。

**打开 SSH / Docker 工作区后目录是空的**
正常。它打开的是本地镜像目录，远端内容用 `remote action=read/list/grep`，或者 `mirror-sync pull`
拉下来。

**`创建并打开` 报目录不存在**
对话框只接受已存在的目录，而且路径是按目标的视角解析的（WSL / Docker / SSH 里写的是那个系统里的
路径，不是 Windows 路径）。

**中文文件名显示成乱码**
和插件无关：那个文件不是 UTF-8。插件按 UTF-8 读写，二进制内容（镜像同步）不受影响。

**卸载插件失败**
见第 1 节最后一段：`file:` 目录必须还在。

## 11. 已知限制

- Docker / SSH 工作区在 DSH 里是本地镜像目录，不是远端真路径；远端文件请走 `remote` 工具。
- 完整「远程」面板（含端口转发的界面入口）默认不注册，需要自行开启 seat。
- SSH 认证支持密钥、agent、password / keyboard-interactive；**不支持需要交互的二次验证**（OTP 弹窗）。
- Docker 目标要求容器是 Linux 且有 `sh`。
- 镜像 push 有 2 秒 mtime 余量，所以刚改过又立刻 push 的文件可能被判为「远端更新」，必要时用 `force`。
- WSL 的大目录（几万个条目）走 UNC 列举会明显变慢，`list` / `glob` 尽量带 `limit`。
